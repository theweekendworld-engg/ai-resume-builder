Patronus — user flows, how they connect, and where people fall out

Audit of production (commit 5a4910e) · 27 Sep 2026 · sources: the code (file:line cited throughout), the production database (read-only), production runtime logs, and live requests against aicv.theweekendworld.com.

Verdict. Adoption is not being lost to small friction. A new person who arrives today cannot reach the product the site promises, and three independent failures make sure of it:
  1. The engine has never run. The daily cron hits /api/cron/tick, which the login middleware answers with 404. No digest, email, GitHub sync, embedding, Radar snapshot or nudge has ever executed in production. The two queued jobs from March are still pending.
  2. The promise is switched off. The landing page sells the Work Log (“merged pull requests come back as drafted wins”). For a new user that feature is either behind an off flag, dependent on the dead engine, or both. What they actually get is a paste-a-job-description resume wizard.
  3. Every handoff drops the user. Score → sign-up loses the fixes. Sign-in loses every deep link. Onboarding sends people to a JD box with an empty profile. Scout knows the job but can't make the resume. Four screens show the same job with different numbers.

So the first job is not new features. It is making one path true end-to-end, and switching off or removing the promises that aren't.

5 · Seven cross-cutting patterns

1. The “always-on” half of the product has never been on

Patronus's difference from a resume builder is that it works without the user: drafting wins from GitHub, the Friday digest, the monthly review, Radar, nudges. All of it runs through one cron that has never reached its handler, a schedule tuned for an hourly tick that became daily, and an email provider that isn't configured. The product's thesis has not been tested even once.

2. Promise ≠ delivery

Marketing, empty states, settings and pricing copy promise things that don't happen: “in about a minute”, “the next sync runs automatically”, “the Friday review”, “fixes ready to apply”, “Weekly digest: Included”, WhatsApp. Each is small; together they teach users that the product's words can't be trusted.

3. Handoffs are where users are lost

Score → sign-up → welcome → build; sign-in → deep link; Scout → resume; extension → tracker → resume; Telegram → the right account. Most individual screens are well built; the joins between them are where state is dropped.

4. Too many surfaces, no spine

Seven dashboard sections, an Inbox with five tabs, a Work Log, a builder, an editor with 14 panels, four job-tracker views, three places to set preferences, two homes. There is no single “here is what to do next” anywhere, and settings aren't reachable on desktop.

5. Charged before value

Generation charges before clarification questions; Scout charges before it knows a note isn't a job; Month in Review charges per view; packets charge before the workflow starts; captures charge twice. On a Free tier measured in single digits, these burn the trial before the user sees the payoff.

6. Configuration drift between code and production

Stripe, Resend and WhatsApp are unconfigured; the workflow SDK was a retired beta; public routes weren't public; the schedule assumed a cron that no longer exists. Nothing checks, at deploy time, that the environment can actually run the features that are switched on.

7. Blind

No landing, sign-up, onboarding or activation event has ever been recorded. The product cannot currently tell you where anyone leaves — which is why an audit like this has to be done by reading code.

What works, and should be the spine

The free ATS check converts attention into a reason to sign up. Scout (link in → fit, pay, interviews, people out, in chat) is the most complete, most “agentic” experience in the product and was verified end-to-end in production on 26 Sep. The Telegram bot, once linked, is genuinely low-friction.

7 · What to do, in order

Ordered by (users affected × how badly) ÷ effort. Tier 0 is roughly a day of work and unblocks most of the product.

Tier 0 — make the machine run this week

  1. Public routes: add /api/cron/tick, /w/(.*), /api/email/unsubscribe, /api/email/webhook, /api/whatsapp/webhook to the self-authenticated list in src/proxy.ts. Verify each returns its own 401, not 404. Unblocks the entire engine and every email action.
  2. A real schedule: either an external hourly pinger (e.g. a free uptime service calling the tick with the bearer) or rewrite schedule.ts for one daily tick (no hour matching; digest due = “this local day, not yet sent”). Enqueue the jobs nothing enqueues: month review, ingest, skill rollup, a daily capture sync. Otherwise fixing the route still leaves most jobs dead.
  3. Configure email (Resend key + EMAIL_FROM) and create EmailPreference at sign-up with the browser's timezone. Zero emails is zero retention loop.
  4. Kick a drain on user actions that expect speed (GitHub repo save, confirm → embed) with after(), so first value doesn't wait for a cron at all.
  5. A deploy-time health check that fails loudly when an on-flag's dependency is missing (flag on + no key, cron route not reachable, workflow start failing). Pattern 6 caused four production outages this week.

Tier 1 — one path, end to end, that keeps its promise next 2 weeks

  1. Score → a fixed resume, no detours. Keep the stash until the editor applies it (server-side, not sessionStorage); onboarding creates a Resume from the imported file and lands in the editor with the fix checklist open. Preferences move to later. This is the only acquisition flow that works; right now it ends in a JD box.
  2. Fix sign-in redirects (honour redirect_url) so extension connect and email links work.
  3. “Tailor my resume for this job” from Scout — on the run page and as a Telegram button — using the JD Scout already stored, creating a per-job copy linked to the tracker row. Joins the product's best feature to its monetised one.
  4. Never overwrite the master on refine; per-job resumes.
  5. One home with a “next step”: pick /home or /dashboard, delete the other route's references, and make the empty state a single action (“Upload your resume” → “Check it against a job” → “Log this week”). Put settings in the desktop nav.
  6. Telegram in one tap: use the deep link the server already returns, refresh status, show which account is linked, add unlink. Detect two accounts under one email at sign-in.

Tier 2 — stop punishing trial users next 2 weeks

  1. Charge at value, not at intent: generation after clarifications; Scout after classification (notes and “other” are free); Month in Review once per month, not per view; packets only after the workflow starts; one charge per capture.
  2. Refund on abandonment and failure everywhere the extension already does.
  3. Wire the existing paywall components; every block shows the plan that unlocks it with a working link.
  4. Configure Stripe (Prices + keys) or remove prices from the product until it is; fix “Add Search” for free users and the $2 < $5 ladder.

Tier 3 — make the Work Log worth the promise month

  1. Fix the first-run state (sourceConnected), save review-queue edits/undo, pass the structured draft, keep the Confirm source, add merge on duplicate.
  2. Decide what “logged” means: a hand-typed win should be confirmed (the user wrote it), not a draft behind a popover.
  3. Make magic-link actions POST (or require a tap on the landing page) so scanners can't act.
  4. One tracker: the Inbox board becomes the only place jobs live; dashboard Applications and the extension list link into it and share its fit numbers and status control.

8 · What to stop doing

Stop adding surfaces. Radar, Missions, Packets, Backfill and Month in Review are built and invisible. Each new feature adds a promise the engine can't yet keep. Freeze feature work until Tier 0–1 ship.
Stop advertising what's off. Remove WhatsApp, the extension, packets and the digest from marketing and empty states until each works for a new user — or show them honestly as “coming”.
Stop shipping without a new-user walkthrough. Every issue in section 3 is visible in ten minutes as a brand-new account. Make “sign up fresh and reach value” a release check, done in production.
